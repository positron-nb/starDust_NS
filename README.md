# Namma Space: smartphone capture to browser walkthrough

Round 1 submission for **Namma Space, Techfest IIT Bombay 2026–27** (3D Reconstruction & Roaming).

The pipeline turns an ordinary smartphone video of a real indoor room into a photorealistic **3D Gaussian Splatting** model. Explore in a **desktop or laptop browser with keyboard and mouse** (WASD + mouse-look), with nothing to install. Touch devices support drag-to-look and on-screen movement arrows.

```
phone video ─► frame extraction + quality gate ─► COLMAP SfM poses ─► Splatfacto (nerfstudio/gsplat)
            ─► ns-export gaussian-splat (.ply) ─► splat-transform (.sog, compressed) ─► Spark.js + Three.js viewer ─► static host
```

> **Live viewer:** **https://stardust-ns.vercel.app/** uses the full room2 reconstruction: **1,296,805 exported Gaussians, 29.41 MiB SPZ**, from a 15:01-minute 4K phone recording. Local GPU COLMAP registered 1,474/1,486 quality-filtered frames (99.2%). Splatfacto trained on **all 1,474 registered frames at 1600×900 for 60,000 iterations** on the local RTX 5060 (WSL2). The viewer includes saved camera views, highlights and touch movement. The model uses a versioned asset URL to avoid stale caches. Current results are in [`submission/room2_full_run.json`](submission/room2_full_run.json), [`submission/technical_abstract.pdf`](submission/technical_abstract.pdf) and [`submission/metrics.md`](submission/metrics.md). Viewer/repository/Drive links are in [`submission/additional_links_and_prototypes.pdf`](submission/additional_links_and_prototypes.pdf). Room2 cold load and sustained FPS have not been benchmarked.

## 1. Run the viewer (Windows, macOS, Linux)

Requires Node.js ≥ 20 (tested with Node 24.19 and npm 11.17).

```powershell
npm ci          # three 0.186.1, @sparkjsdev/spark 2.3.1, vite 8.3.4 (exact pins)
npm run dev     # http://localhost:5173
```

| Control | Action |
|---|---|
| Click **Start walkthrough** | Locks the mouse pointer |
| `W A S D` / arrows | Walk (1.4 m/s) |
| Mouse | Look |
| `Shift` | Walk faster (2×) |
| `Q` / `E` | Lower or raise eye level (±0.6 m) |
| `R` | Reset to start pose |
| `F` / `I` | Fullscreen / technical HUD |
| `Esc` | Release mouse (pause). The dock's exit button ends the walkthrough. |

The room2 experience also includes **saved viewpoints** (room overview, window and workspace), an optional **highlight slideshow**, a live **walk-boundary map**, and shareable viewpoint links (`?view=0`, `1` or `2`). These are camera views, not obstacle-aware navigation. Use the picture icon in the floating dock to return to the viewpoint gallery. The **?** button opens controls and display-quality settings; local file loading and calibration remain available. Saved room2 views are hidden for other models and in calibration mode.

If the browser refuses pointer lock (for example inside an iframe), the viewer falls back to drag-to-look. URL options: `?calibrate` opens the alignment panel, `?dpr=1` lowers render resolution on weak GPUs, and `?manifest=models/other.json` loads another manifest.

Production build: `npm run build` writes a static site to `dist/`, and `npm run preview` serves it locally.

## 2. Reconstruct a room

Follow [`capture_sop.md`](capture_sop.md) to record `capture/room.mp4` (the folder is git-ignored). Then run the pipeline using one of the options below.

**Option A, hosted GPU (recommended):** open `notebooks/namma_space_colab.ipynb` in Google Colab ([open in Colab](https://colab.research.google.com/github/positron-nb/starDust_NS/blob/main/notebooks/namma_space_colab.ipynb)) with a GPU runtime, upload the video and run all cells. Download `<RUN_ID>_web.zip` (model and draft manifest) and `<RUN_ID>_outputs.zip` (metrics, reports, COLMAP poses, PLY).

**Option B, local:** see [`docs/environment.md`](docs/environment.md) for the CUDA/COLMAP/nerfstudio install, then:

```powershell
.\scripts\run_reconstruction.ps1 -Video capture\room.mp4 -RunId bedroom-v1
# resume a run from a stage:   -RunId bedroom-v1 -SkipTo colmap | train | export | web
# photos instead:              -Images capture\photos -Matching exhaustive
# gates:                       -MinFrames 40 -MinRegistered 0.7 (defaults)
```

Each run lives in `data/runs/<RunId>/`, and nothing is shared between runs. An existing run folder is never reused unless you pass `-Force`. Every native command is checked as soon as it exits. Each stage clears its own outputs first and checks they were freshly written. Export uses the training config recorded for *that* run, not "the newest one on disk". Two gates stop the run before GPU time is wasted:

- **Quality gate:** fewer than `MinFrames` usable frames makes `check_images.py` exit with code 3.
- **Registration gate:** if registered cameras ÷ frames used is below `MinRegistered`, the run stops after COLMAP.

| Stage | Command (paths relative to `data/runs/<RunId>/`) | Output check |
|---|---|---|
| frames | `extract_frames.py <video> images --fps 2 --max-width 1600`, then `check_images.py images --move-rejects --min-frames 40` | gate: usable frames ≥ 40 |
| colmap | `ns-process-data images --data images --output-dir processed --matching-method sequential` | fresh `transforms.json`, registration ratio ≥ 0.7 |
| train | `ns-train splatfacto --data processed --output-dir outputs --experiment-name <RunId> --timestamp run --max-num-iterations 30000 --viewer.quit-on-train-completion True` | exactly one `config.yml`, path saved in metrics |
| export | `ns-export gaussian-splat --load-config <recorded config> --output-dir exports` | exactly one fresh `.ply` |
| web | `splat-transform <ply> --filter-nan public/models/<RunId>.sog -w`, then `splat_info.py --manifest-out public/models/<RunId>.manifest.json` | fresh `.sog` and draft manifest |

`run_metrics.json` has the same schema on Windows and Linux. File sizes are exact bytes (`export_ply_bytes`, `web_model_bytes`), and durations are seconds per stage.

## 3. Replace the model with a newly captured room

The pipeline never touches the live viewer. A run produces `public/models/<RunId>.sog` and a **draft** manifest `public/models/<RunId>.manifest.json`, marked `"calibrated": false`. The draft already has the z-up → y-up rotation and a floor height, bounds and start point estimated from splat percentiles (offline, so the browser doesn't have to compute them). To publish a run:

1. Run `npm run dev` and open `http://localhost:5173/?calibrate&manifest=models/<RunId>.manifest.json`.
2. Check the alignment:
   - Use **Rotate X/Y/Z** until the walls are vertical and the floor is level.
   - Use **Scale** until a known dimension looks right. COLMAP is scale-free; a door should be about 2 m high.
   - **Fit bounds** re-estimates the floor and the rectangle from sampled splats.
   - **Walk outline:** walk to each floor corner in order and press **Add corner** (the boundary is off while recording), then **Finish outline** to activate it. The polygon replaces the rectangle, and every step is checked as a path against its walls, so irregular or L-shaped rooms don't let you cross outer walls.
   - Walk to the entrance and press **Set start here**.
   - Tick **Mark as calibrated**, press **Copy manifest JSON**, and paste the result into the draft file.
3. Publish it: `Copy-Item public\models\<RunId>.manifest.json public\models\manifest.json`.
4. Run `npm test` (which validates the published manifest and checks its model file exists), then `npm run build`, and redeploy.

The viewer validates every manifest before loading. Invalid fields (for example a negative scale, a malformed start position, `min ≥ max` bounds or a degenerate polygon) stop loading with a field-by-field error message. Spark also loads `.ply`, `.spz`, `.splat` and `.ksplat` files.

## 4. Asset size and deployment strategy

| Model size (web file) | Strategy |
|---|---|
| ≤ 50 MB | Commit to `public/models/` (GitHub warns above 50 MB per file) and deploy `dist/` to Vercel, Netlify or GitHub Pages. |
| 50–90 MB | Keep it out of git and deploy `dist/` straight from the CLI (Vercel Hobby allows 100 MB of uploaded static files in total). Better: shrink it with splat-transform `-H 2` (drop the 3rd SH band) or `--decimate 70%`. |
| > 90 MB | Host the model on object storage with CORS (Cloudflare R2, Hugging Face dataset, GitHub Release asset behind a CORS proxy) and put the absolute URL in `manifest.json → file`. |

SOG compresses a PLY by roughly an order of magnitude. The synthetic 5.1 MB PLY becomes a 0.15 MB SOG, but real scenes compress less because they carry full spherical harmonics, so record the measured ratio in `submission/metrics.md`. Full notes are in [`docs/deployment.md`](docs/deployment.md).

## 5. Tests

```powershell
python -m pip install -r requirements.txt; npm ci
npm test         # 19 JS tests (manifest validation, walk area) + 5 Python tests (frames, quality gate, splat info)
npm run build
```

GitHub Actions (`.github/workflows/ci.yml`) runs a clean install, the tests, the production build, a check that the built site contains the published manifest and its model, and a syntax check of the bash pipeline. Manual checks (real pointer lock, real-model FPS) are listed in [`test/README.md`](test/README.md).

## 6. What this is not

- **No collision detection.** Gaussian splats have no surfaces. The viewer keeps the camera at a fixed eye height above a calibrated floor and inside a calibrated floor outline (or, failing that, a rectangle). That stops you leaving the room but does not stop you walking through furniture. Obstacle-aware navigation (a separate occupancy grid or navmesh plus A*) is Round 2 scope; the visual splats are not used as collision geometry.
- No POIs, pathfinding or AR in Round 1.
